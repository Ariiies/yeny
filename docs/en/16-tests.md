# Tests

This guide explains how to run the Yeny test suite from a local copy of the repository.

If you just cloned the project, this is the page you should read first to validate that everything works locally.

## Testing structure

```text
tests/
├── conftest.py
├── test_utils/
├── test_core/
├── test_persistence/
└── test_integration/
```

## What each folder covers

- `tests/test_utils`: tokenization, compaction, serialization, parallelization and mmap.
- `tests/test_core`: behavior of `CoreEngine` and `LiteEngine`.
- `tests/test_persistence`: saving, loading, versioning and rollback on SQLite.
- `tests/test_integration`: End-to-end `Yeny` public API.

## Preparation

Install the test dependencies in your virtual environment:

```bash
python -m pip install pytest pytest-cov pytest-mock
```

If you want to run the tests with the same version of the interpreter used by the project, activate your virtual environment or conda first and then install the dependencies there.

If you are editing the project while testing, install the package in editable mode:

```bash
python -m pip install -e .
```

## Run all tests

```bash
python -m pytest
```

This command runs the entire suite under `tests/`.

## Run by area

```bash
# Utilidades
python -m pytest tests/test_utils -v --tb=short

# Motores de búsqueda
python -m pytest tests/test_core -v --tb=short

# Persistencia y rollback
python -m pytest tests/test_persistence -v --tb=short

# Integración de la API pública
python -m pytest tests/test_integration -v --tb=short
```

If you just want to validate the new persistence and rollback flow, run:

```bash
python -m pytest tests/test_persistence -v --tb=short
```

## Run by bookmark

Yeny uses markers to separate quick integration tests:

```bash
python -m pytest -m unit
python -m pytest -m integration
```

## Coverage

```bash
python -m pytest --cov=src/yeny --cov-report=html
```

This generates an HTML report with coverage details.

To see a quick summary in the console:

```bash
python -m pytest --cov=src/yeny --cov-report=term-missing
```

## What to try first

If you just cloned the repo, this is the safest order:

1. `python -m pytest tests/test_utils -v --tb=short`
2. `python -m pytest tests/test_core -v --tb=short`
3. `python -m pytest tests/test_persistence -v --tb=short`
4. `python -m pytest tests/test_integration -v --tb=short`

If you are fixing a specific bug, rerun just the affected folder before running the entire suite.

## Practical notes

- Persistence tests use temporary SQLite databases.
- Integration tests use small data and do not require external services.
- If a test fails due to a temporary file, delete the directory generated by `tmp_path` and run again.
- Rollback tests assume that the SQLite backend maintains historical versions of the same index.

## How to expand the suite

- Add edge cases in `tests/test_utils` for pure functions.
- Use `tests/test_persistence` for save/load, versioning and rollback.
- Use `tests/test_integration` to validate the `Yeny` public API.

## Recommended flow for contributors

1. Run the tests for the folder you are going to touch.
2. Fix the bug closest to the expected behavior.
3. Run the affected folder again.
4. Run the complete suite before opening a PR or preparing a release.
